# Руководство по реализации Backend

Пошаговый план реализации бэкенда на Flask + PostgreSQL с чекпоинтами для отслеживания прогресса.

---

## Этап 1: Подготовка окружения

- [ ] **1.1** Создать папку `backend/` в корне проекта
- [ ] **1.2** Создать виртуальное окружение Python (`python -m venv venv`)
- [ ] **1.3** Активировать виртуальное окружение
- [ ] **1.4** Создать файл `requirements.txt` с зависимостями (Flask, Flask-CORS, Flask-SQLAlchemy, psycopg2-binary, python-dotenv)
- [ ] **1.5** Установить зависимости (`pip install -r requirements.txt`)
- [ ] **1.6** Создать файл `.env` с переменными окружения (DATABASE_URL, SECRET_KEY)
- [ ] **1.7** Запустить PostgreSQL через Docker (`docker-compose up -d postgres`)
- [ ] **1.8** Проверить подключение к базе данных

---

## Этап 2: Структура проекта

- [ ] **2.1** Создать структуру папок:
  ```
  backend/
  ├── app/
  │   ├── __init__.py
  │   ├── config.py
  │   ├── models/
  │   ├── routes/
  │   ├── services/
  │   └── utils/
  ├── run.py
  └── requirements.txt
  ```
- [ ] **2.2** Написать `app/__init__.py` — инициализация Flask приложения
- [ ] **2.3** Написать `app/config.py` — конфигурация (подключение к БД, секретный ключ)
- [ ] **2.4** Написать `run.py` — точка входа для запуска приложения
- [ ] **2.5** Проверить, что приложение запускается (`flask run`)

## Этап 4: API — Работа с характеристиками

### 4.1 Получение характеристик

- [ ] **4.1.1** Создать `app/routes/__init__.py`
- [ ] **4.1.2** Создать `app/routes/features.py` с Blueprint
- [ ] **4.1.3** Реализовать `GET /api/cards/{card_id}/features` — получить список характеристик
- [ ] **4.1.4** Добавить фильтрацию по `only_significant` параметру
- [ ] **4.1.5** Протестировать эндпоинт через Postman/curl

### 4.2 Пометка характеристики как незначимой

- [ ] **4.2.1** Реализовать `POST /api/cards/{card_id}/features/mark-insignificant`
- [ ] **4.2.2** Обновить поле `is_significant = False` в таблице `card_features`
- [ ] **4.2.3** Если `apply_to_category = true`, обновить `category_feature_significance`
- [ ] **4.2.4** Создать запись в `feature_change_logs` с `became_insignificant = True`
- [ ] **4.2.5** Протестировать эндпоинт

### 4.3 Добавление характеристики в значимые

- [ ] **4.3.1** Реализовать `POST /api/cards/{card_id}/features/mark-significant`
- [ ] **4.3.2** Обновить поле `is_significant = True` в таблице `card_features`
- [ ] **4.3.3** Если `apply_to_category = true`, обновить `category_feature_significance`
- [ ] **4.3.4** Создать запись в `feature_change_logs` с `became_significant = True`
- [ ] **4.3.5** Протестировать эндпоинт

### 4.4 Изменение значения характеристики

- [ ] **4.4.1** Реализовать `PATCH /api/cards/{card_id}/features/change-value`
- [ ] **4.4.2** Проверить, что `old_value` совпадает с текущим значением
- [ ] **4.4.3** Обновить `feature_value` на `new_value`
- [ ] **4.4.4** Создать запись в `feature_change_logs` с `old_value` и `new_value`
- [ ] **4.4.5** Протестировать эндпоинт

### 4.5 Получение доступных характеристик

- [ ] **4.5.1** Реализовать `GET /api/cards/{card_id}/available-features`
- [ ] **4.5.2** Получить все характеристики из категории карточки
- [ ] **4.5.3** Вернуть список с `usage_count` и `is_significant_in_category`
- [ ] **4.5.4** Протестировать эндпоинт

## Быстрые команды

```bash

pip install -r requirements.txt

# Запуск PostgreSQL
docker-compose up -d postgres

# Запуск Flask
flask run

# Запуск тестов
pytest
```
